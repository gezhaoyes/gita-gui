# gita-gui 计划书

> 版本：最终版 · 2026-10-18

## 1. 目标

把 Windows 和 WSL 两边的 git 仓库放在一张表里，一眼看出哪些还没推送，并能一键推送。同时维护一份仓库清单，换电脑或重装系统后，可以从清单一键 clone 回来。工具直接读写 gita 的登记数据，和 gita 命令行互通。

**做**：状态总览、添加仓库、推送、自动维护清单、从清单 clone。
**不做**：提交、pull、fetch、列出未提交的文件、紧急备份。

## 2. 已定决策

| 项 | 决定 |
|---|---|
| 技术栈 | Tauri 2：Rust 后端 + Vue 3 前端 |
| git 在哪执行 | 仓库在哪一边，就用哪一边的 git，不跨边操作 |
| WSL 侧 | 不部署任何东西。Rust 把一批 git 命令打包，通过一次 `wsl.exe -- sh` 调用执行完 |
| git 操作方式 | 调用 git 命令行，不用 Rust 的 git 库。这样认证和配置都和平时用的 git 一致 |
| 仓库来源 | 只有一个"添加"操作：选中的文件夹本身是仓库就直接加入；不是就往下找，列出找到的仓库，勾选后加入 |
| 未提交的改动 | 只打一个标记，提交去编辑器里做 |
| 推送 | 只推已经提交的内容 |
| WSL 认证 | WSL 的 git 借用 Windows 的 Git Credential Manager，两边共用一次 GitHub 登录 |

## 3. 架构

```
┌──── gita-gui（Tauri）──────────────────────────────┐
│  前端 Vue 3：总表 · 添加 · 推送 · 导出清单 · clone   │
│        ↕ Tauri 内部调用                             │
│  Rust 后端：执行命令 · 解析状态 · 判断颜色 · 清单      │
└──────┬──────────────────────────────┬─────────────┘
       │ 直接运行 git / gita           │ wsl.exe -d Ubuntu -- sh（一次跑一批命令）
   Windows 仓库                    WSL 仓库
```

- 所有 git 调用都设置 `GIT_TERMINAL_PROMPT=0`（缺凭据时直接报错，不卡住），并强制 UTF-8 输出。
- 读 WSL 侧数据时，一次调用拿回所有仓库的结果。推送则每个仓库单独调用一次。

## 4. 技术栈

| 部分 | 选择 |
|---|---|
| 框架 | Tauri 2（使用 Windows 11 自带的 WebView2） |
| 后端 | Rust（本机已有 1.99 MSVC 版和 VS 2022 生成工具） |
| 前端 | Vue 3 + TypeScript + Vite |
| 界面组件 | Naive UI（表格自带排序、筛选、勾选） |
| 包管理 | npm（前端）+ cargo（后端） |
| 测试 | Rust 单元测试，在临时目录里建测试仓库 |
| 发布 | Tauri 自带打包，生成安装包或单个 exe |

## 5. 状态定义

| 颜色 | 含义 |
|---|---|
| 🟢 绿 | 已备份：没有未推送的提交，也没有未提交的改动 |
| 🟡 黄 | 有未提交的改动 |
| 🔴 红 | 有未推送的提交，或者分支没有设置上游，或者没有远程仓库 |
| ⚪ 灰 | 登记的路径已经不存在 |

- 同时满足多种情况时，按最严重的显示：灰 > 红 > 黄 > 绿。
- 状态来自 `git status --porcelain=v2 --branch`。工具不做 fetch，"未推送"是和本机记录的远程状态比较；每次从本机推送后这个记录都会更新。

## 6. 后端命令（前端可以调用的操作）

| 命令 | 作用 |
|---|---|
| `load_repos` | 读取一边的 gita 登记（路径、名字、分组、路径是否存在）和每个仓库的状态（分支、上游、未推送数、有无未提交改动、远程地址）；读取成功后顺带同步这一边的清单。WSL 侧共两次 `wsl.exe` 调用 |
| `discover` | 从选中的目录往下找仓库。找到 `.git` 就停，跳过 `node_modules`、`build`、`Debug`、`Release`、`.venv`，有深度上限。Windows 侧用 Rust 遍历目录，WSL 侧用 `find` |
| `add_repos` | 调用 `gita add` 登记，可同时加入分组 |
| `remove_repo` | 取消登记（不删文件）。直接从 repos.csv / groups.csv 删掉这一行，见第 8 节 |
| `relocate_repo` | 重新定位：取消旧登记、登记新路径、恢复原来的分组 |
| `push` | 推送。失败原因分为：认证 / 无上游 / 被拒绝 / 网络 / 其他 |
| `push_set_upstream` | 分支没有上游时，设置上游并推送。前端先让用户确认 |
| `overwrite_manifest` | 清单冲突时，用本机登记强制覆盖 |
| `read_manifest` / `clone_entry` | 读取清单；按清单的一条 clone，完成后自动登记并恢复分组（前端逐条调用，显示进度） |
| `setup_wsl_auth` | 一键让 WSL 的 git 借用 Windows 的 Git Credential Manager |
| `open_in_explorer` / `open_in_editor` | 在资源管理器或 VS Code 中打开。WSL 仓库在资源管理器里用 `\\wsl.localhost\Ubuntu\...` 路径；在 VS Code 里用 `code --remote wsl+Ubuntu` 打开 |

## 7. 界面与功能

1. **总表**
   - 列：状态、环境、名字、分组、分支、未推送、未提交标记、远程
   - 远程列显示上游所在远程的地址；这个远程配了多个推送地址（`pushurl`）时显示 `+N`，悬停列出所有推送地址，推送地址里不含拉取地址时额外提醒
   - 筛选：按环境、按分组、只看没备份的
   - 先显示 Windows 仓库，WSL 的数据到了再补进来
   - 自动刷新：启动时；在工具里添加、移除、重新定位、推送、恢复之后；切回窗口时（两次至少间隔 15 秒，有对话框打开时不刷新）。也可以手动点"刷新"
2. **添加**：点按钮选文件夹，或把文件夹拖进窗口，规则见第 2 节。已经登记的仓库显示为灰色。
3. **推送**
   - 可以推单个、选中的或全部仓库；结果逐行显示，失败的可以重试
   - 批量推送时一个接一个推，避免同时弹出多个登录框
   - 被远程拒绝（远程有本地没有的提交）时，提示去编辑器处理
   - 认证失败时按仓库所在的一边提示：WSL 仓库提示"WSL 侧未配置 GitHub 认证"，并提供一键配置；Windows 仓库提示重试时会弹出 Git Credential Manager 登录
   - 没有上游的仓库不自动推，列出来让用户确认后再设置上游
   - 推送失败会被记下（存在工具配置里），之后即使 git 显示已推送也继续标红、原因写"上次推送有失败"，直到在工具里再推送成功。用于一个远程配多个推送地址、一处成功一处失败的情况：git 只有一份 `origin/main` 记录，一处成功就会把未推送数清零
4. **清单（自动维护）**
   - 两份清单，和两边的 gita 登记一一对应：`manifest-windows.json`、`manifest-wsl.json`，都放在配置指定的清单目录里，默认是 OneDrive 下的一个文件夹，首次使用时让用户确认。同步到远程交给 OneDrive，工具只管写文件
   - 清单是从 gita 登记派生出来的副本，不手工编辑。gita 登记才是源头；它本身留在本机原位，不挪到 OneDrive（里面没有远程地址，光靠它没法 clone）
   - 每个仓库记录：路径、远程地址、分支、分组，以及推送地址（只在一个远程推到多处时记录，恢复时用 `git remote set-url --add --push` 配回去）。按路径排序，不写时间戳、未推送数这类易变字段，保证内容不变时文件也不变，免得 OneDrive 白白同步
   - 触发更新：添加、移除、重新定位之后；每次启动或刷新时（覆盖在 gita 命令行里做的改动，以及远程地址、分支的变化）。内容有变化才写入
   - 两边各管各的：哪一边读取成功就只更新哪一边的清单。WSL 没启动或读取失败时不动 `manifest-wsl.json`，不能当成"WSL 没有仓库"
   - 防止误覆盖：配置里给每份清单记下上次写入内容的哈希。如果文件当前内容和哈希对不上（别的电脑写过，或手工改过），不覆盖，提示用户选"从清单恢复"或"用本机覆盖"。新电脑上登记是空的，靠这条保证不会一启动就把清单清空
   - 写入时先写临时文件再改名，避免 OneDrive 同步到写了一半的文件
   - 没有远程仓库的仓库无法恢复，在总表里标出来
5. **从清单 clone**
   - 打开清单后勾选要恢复的仓库
   - 按"环境"决定 clone 到 Windows 还是 WSL
   - 目标路径默认用清单里记录的路径，可以改
   - 本地已经存在的跳过
6. **右键菜单**：在资源管理器中打开、在 VS Code 中打开、重新定位、移除登记。

## 8. 配置

- **gita 的登记文件**：两边各一份，工具不改它的格式。读取时直接解析文件；添加和分组调用 gita 命令。
  - 取消登记不用 `gita rm`：它会按"路径是否存在"过滤后重写整个文件，顺带删掉所有路径暂时不存在的登记，而且删不了路径已经不存在的登记。工具自己从 repos.csv / groups.csv 里删掉那一行，按 gita 的格式（Python csv 默认格式，`
` 换行）和原编码写回
  - Windows 版 gita 用系统默认编码读写文件（中文系统是 GBK），读取时先按 UTF-8，失败再按 GBK
- **工具自己的配置**：使用 Tauri 的应用配置目录，存这些内容：
  - WSL 发行版名
  - 清单目录（默认 OneDrive 下），以及两份清单各自上次写入内容的哈希
  - 编辑器命令、Windows 侧 gita 命令
  - 往下找仓库时要跳过的目录和深度
  - 窗口布局（tauri-plugin-window-state 自动保存）

## 9. 工程结构

```
D:/code_win/gitaGUI/
├─ docs/计划书.md
├─ src/                  前端 Vue
│  ├─ views/             总表、添加、推送、清单恢复、设置对话框
│  ├─ store.ts           两边的仓库数据和加载状态
│  └─ api.ts             封装对后端命令的调用
└─ src-tauri/src/
   ├─ exec.rs            执行命令：本机直接运行 / WSL 批量运行
   ├─ config.rs          工具自己的配置
   ├─ gita.rs            读 gita 登记文件，调用 gita add，取消登记
   ├─ status.rs          解析 git status，判断颜色
   ├─ discover.rs        往下找仓库
   ├─ push.rs            推送和错误分类
   ├─ manifest.rs        生成并同步清单、按清单 clone
   └─ commands.rs        暴露给前端的命令
```

## 10. 实施步骤

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **M0 环境准备** | 两边安装 gita（Windows 用 pipx；WSL 的 `sudo apt` 需要密码，改为装在 `~/.local/share/gita-venv`，链接到 `~/.local/bin/gita`）；WSL 配好 Git Credential Manager；用官方模板（Vue + TS）建 Tauri 工程并推到 GitHub | 在普通 WSL 终端里执行 `git push --dry-run` 成功；Tauri 空窗口能运行 |
| **M1 Rust 核心** | 写好 `exec`、`gita`、`status`，以及对应的单元测试 | 两边仓库的状态解析结果和 `git status` 一致 |
| **M2 总表** | 表格、颜色、筛选，WSL 数据异步补进来 | 打开窗口几秒内看到所有仓库 |
| **M3 添加** | `discover` 和 `add`，加上对话框和拖放 | 选一个父目录能找到下面所有仓库；加入后用 `gita ll` 也能看到 |
| **M4 推送** | 单个和批量推送、错误分类、设置上游、认证提示 | 断网或缺凭据时不卡死，能看到明确的原因 |
| **M5 清单** | 自动维护两份清单（含误覆盖保护），从清单 clone | 添加一个仓库后 OneDrive 里对应的清单自动更新；WSL 没启动时 WSL 清单保持不变；删掉一个测试仓库后能从清单恢复，分组也还在；新机器空登记启动时不会把清单清空 |
| **M6 收尾** | 右键菜单、失效登记处理、打包 | 安装后可以日常使用 |

## 11. 注意点

- **WSL 冷启动慢**：WSL 平时是停止状态，第一次调用可能要等几秒，所以界面先显示 Windows 的仓库。
- **编码**：`wsl.exe` 自己的提示信息是 UTF-16 编码，git 的输出是 UTF-8，Rust 里两种都要处理。
- **拼 shell 脚本时的路径转义**：仓库路径里可能有空格或中文，传给 WSL 的路径必须统一做 shell 转义。脚本通过 stdin 传给 `wsl.exe -- sh -s`，避开 wsl.exe 自己的参数转义。
- **WSL 的 PATH**：`sh` 不读 `.bash_profile`，脚本开头自己把 `~/.local/bin` 加进 PATH。
- **git 输出语言**：所有 git 调用设 `LC_ALL=C`，保证错误信息是英文，推送失败才能正确分类。
- **第三方仓库**（比如 `~/linux`）：推送不了，会一直标红。第一版先用分组筛选把它们挡掉，以后再考虑加"只跟踪"类别。
